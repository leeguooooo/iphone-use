Getting Started

iphone-use

Let AI agents use your real iPhone. With iphone-use installed on your Mac, Claude Code, Codex or any MCP client reads the phone's screen as text, taps, types and swipes in any app, including the ones with no API: Health, banking, chat apps, or the app you are testing. You can watch it live and take the phone back at any time.

bash · on the Mac the iPhone is plugged into 
$ curl -fsSL https://raw.githubusercontent.com/leeguooooo/iphone-use/main/install.sh | sh

Connect your agent in three steps

  1. Get the phone ready: a Mac with macOS 15 or later, Xcode and an Apple ID; an iPhone with iOS 15 or later; and a USB cable for the first setup. Enable Developer Mode on iOS 16 or later (Settings → Privacy & Security → Developer Mode). A free account works on iOS 17 or later; the iOS 15/16 path on Xcode 26 or later needs a paid account’s App Store Connect API key: see installation requirements. Plug the iPhone in and unlock it.
  2. Run the installer above. It sets the phone up, shows an agent opening Settings and reading it, registers the MCP server with Claude Code and Codex (and with Cursor and Claude Desktop when they are installed), and opens the control page in your browser with a one-time sign-in. If anything is missing, it says what and how to fix it.
    bash 
    $ iphone-use doctor   # what is missing, and how to fix it
$ iphone-use try      # a harmless check: open Settings, read the screen, go Home
  3. Ask your agent. Start a new chat in Claude Code or Codex and say what you want done on the phone. You do not need to learn any commands; the bundled skill teaches the agent the loop. Other clients: MCP, HTTP API and skill.

Ask your agent

Requests like these work in any app on the phone. The agent finds an app by its name, types long text in one step and reads a list across pages.

❤️ Read data out of apps

Open Health and tell me how many steps I walked each day this week.

The screen comes back as text (an accessibility tree), not pixels.
💬 Chat apps with no API

Find the newest message from Mom in WeChat and read it to me.

Taps, typing (CJK included) and swipes go through a small XCTest runner on the phone.
🏦 Long lists, to the end

Collect every transaction on this bank statement page, all the way to the end.

It reads a list across pages and says whether it reached the end. Screens hidden from capture are driven by their elements.
📝 Long text in one step

Write this 2,000-word draft into a new note in Notes.

Up to 20,000 characters in one typing step.
🧪 Test your own app

Run my app's login test on the real phone and tell me which step fails.

Logs, crash reports, screen recording, installing a build and a simulated location are in the same tools.
🔁 Do it once, replay it

Save what you just did as a flow so it runs in one call next time.

A saved flow replays with no model and no tokens.

Without the terminal

🤖 Let the agent install it

Paste one prompt into Codex or Claude Code. It runs the installer and stops for the steps only you can do, such as tapping Trust on the iPhone. It never asks for a password or a code.
🖥️ Drive it from a browser

A live H.264 screen: click to tap, drag to swipe, type with your own input method. The Flow panel records what you do.
📲 Remote control from another iPhone

Pair by scanning a code, then watch, tap, swipe and type. The controlled phone can run the control service itself with no computer, and a self-hosted Cloudflare relay lets you connect from cellular, anywhere.
🤖 The phone drives itself

Tell the assistant on the iPhone what to do, and it operates that same phone and reports back. No computer; the model uses your own key.
👀 Watch the agent live

The phone's screen shows in the agent host's side panel where MCP Apps is supported, in a browser, or in the iOS app.

Why a real iPhone

🔓 Any app, no API needed

Health, banking and payment apps (even the ones that black out screen capture), chat apps, and your own app under test, with the sign-ins already on the phone.
📶 USB or Wi-Fi, old iPhones too

Set the phone up once with a cable; then drive it over Wi-Fi through an encrypted tunnel. iOS 15 and later, without updating the phone.
✅ Honest results

Every action reports whether it was applied, not sent, or unknown, and whether a retry is safe. Taps on covered elements are refused.
🖱️ Nothing on the Mac moves

It never touches the Mac's screen, cursor or focus. Agents and people share the phone; one of them holds it at a time.
ℹ️ Speed, as measured by the maintainer
On the same iPhone 13 over USB (October 2026), the iphone-use runner read the screen in 0.08–0.135 s and a tap plus waiting for the screen to settle took 1.0 s; agent-device took about 0.7 s and 2.8–3.3 s. Through the full agent API, a tap by label that returns the settled change took about 1.9 s on an iPhone 17 Pro Max. These are the project's own measurements from its README, not an independent benchmark.

Under the hood

One daemon per phone runs on your Mac. It reads the screen as an accessibility tree, sends taps and typing through its own XCTest runner on the iPhone, and checks that the screen has settled before it answers.

Quick answers

Does it need a jailbreak?

No. It needs a signed XCTest runner, and Developer Mode on iOS 16 or later, which the installer builds with your Xcode team.

Which agents can use it?

Claude Code, Codex, Cursor, Claude Desktop and any other MCP client, through the bundled MCP server. Scripts and other agents can call the HTTP API under /agent/*.

Does it need a Mac?

Yes. The daemon runs on a Mac with macOS 15 or later and Xcode. Other devices can reach its browser page and APIs, but the phone itself is hosted by the Mac.

Is it free and open source?

It costs nothing to download and use. It is source-available under the PolyForm Shield 1.0.0 license, not an OSI-approved open-source license: non-competing use, modification and distribution are permitted, while using it to provide a competing product or service is not.
