iphone-use 和其他 iPhone 自动化方案对比

让 agent 或测试操作 iPhone 的项目有好几个。它们的区别在于面向什么设备、怎么连到真机、拿来做什么。 这里只比较事实，不排名次。

2026-10-27 核对，依据各项目自己的 README。项目会更新，以链接里的当前状态为准。

iphone-use 侧重什么

  • 你自己的真实 iPhone 和上面已有的 App，带着登录状态：健康、银行、聊天 App、你在测的 App。手机由你 Mac 上的守护进程托管。
  • 自研 XCTest 设备 runner，从 v0.14.0 起取代 WebDriverAgent，保留 WebDriverAgent 的 HTTP API。发给它的请求按每次启动签名。
  • 明确的动作结果：已执行、没发出去或不确定，附带 retry_safe；点到被遮住的元素会被拒绝。
  • 确定性的 flow 重放，来自经过审阅的 flow 源，不经过模型。
  • 人和 agent 共用一台手机：网页和 iOS App 远程控制，同一时间只有一个使用者。
  • 宿主是 Mac，操作的是 iPhone（以及预览中的 iOS 模拟器），不支持 Android 设备。

怎么选

📱 在自己的 iPhone 上用日常 App

从没有 API 的 App 里读数据，你能看着、能随时接手：这是 iphone-use 的设计目标。

🤝 一个工具同时管 iOS 和 Android

agent-device 和 Mobile MCP 都覆盖 iOS 和 Android 的模拟器与真机，也能接设备云。

🧪 维护一套 WebDriver 测试

Appium 加 XCUITest driver 是成熟的 WebDriver 生态，适合跨平台端到端测试。

🐍 自带循环的 Python agent

ios-agent 提供终端 agent、MCP server 和 Python 库，支持 iOS 模拟器和真实 iPhone。

一组实测对比

ℹ️ 维护者实测，不是第三方评测
iphone-use 的 README 记录了同一台 iPhone 13、USB 连接下的结果（2026 年 10 月）：读屏 iphone-use runner 用 0.08–0.135 秒， agent-device 约 0.7 秒；点击并等画面稳定分别是 1.0 秒和 2.8–3.3 秒。本页其他工具没有被项目实测过。比较速度需要同一台设备、 同样的操作和同样的等待条件。
